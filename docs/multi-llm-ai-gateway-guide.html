Control Flow

一次模型請求如何被治理

控制不是在 Provider 呼叫之後補做，而是在 request path 上逐層 gate，先拒絕不合規請求，再進入模型選擇與成本累積。

Authenticate解析 X-API-Key 或 OIDC Bearer JWT，建立 Principal。
AuthorizeRBAC：viewer / operator / admin，Chat Completion 至少需要 operator。
Policy依 priority 對 role、client、model glob、stream、max_tokens 做 allow/deny。
Rate LimitGlobal RPM 或 per-client RPM override，Redis 模式跨 replicas 共用。
BudgetDaily / Monthly cost budget gate。
Routealias / pool → priority、round-robin、random 或 cost-aware。
ResilienceRetry、Fallback、Circuit Breaker 避免單一 Provider 失敗擴散。
RespondBuffered JSON 或 OpenAI-compatible SSE streaming。
RecordUsage、Token、Cost、Prometheus Metrics、OTel Trace、Audit。
ObserveGrafana / Prometheus / OTel 提供可視化與後續告警基礎。

Policy Engine

模型請求在進 Provider 前就能被阻擋

Policy 不是模型路由的同義詞，而是治理條件。規則依 priority 排序，第一個符合的 rule 決定 allow / deny 或附加限制。

Match dimensions

rolesclientsmodelsallow_streammax_tokens

Model 支援 glob pattern，例如 openai:* 或 mock:secret*。

Why before routing?

先拒絕沒有權限或違反政策的 request，可避免不必要的 upstream cost、降低資料外洩風險，也讓 policy rejection 可被獨立觀測。

Deny model family
curl -X PUT http://localhost:8000/admin/api/policies/block-secret \
  -H 'X-Admin-Key: dev-admin-key' \
  -H 'Content-Type: application/json' \
  -d '{
    "priority":1,
    "effect":"deny",
    "models":["mock:secret*"]
  }'
Deny streaming
{
  "priority":10,
  "effect":"allow",
  "roles":["operator"],
  "models":["mock:*"],
  "allow_stream":false
}

Interview View

面試官 5 分鐘快速導覽

如果面試時間有限，建議依「問題 → 架構 → 關鍵決策 → 證據 → trade-off」的順序展示，不要從 README 第一行一路念。

01 · Problem

為什麼需要 Gateway？

企業同時有 RAG、Agent、內部應用，若每個系統直接綁 OpenAI / Anthropic / Gemini，就會出現 SDK、Credential、Policy、Budget、Fallback 與 Observability 分散問題。

02 · Architecture

怎麼集中治理？

使用單一 OpenAI-compatible endpoint，把 Identity → Policy → Rate/Budget → Router → Resilience → Usage/Trace 串成固定 control path。

03 · Distributed Design

怎麼支援多 replicas？

把 rate window、round-robin cursor、circuit state、usage/cost、dynamic governance、clients/policies 移到 Redis，並用兩個獨立 Redis clients 做 integration proof。

04 · Security

怎麼做到企業 Identity？

API Key 向下相容；OIDC/JWT 可選啟用，驗 signature/JWKS、issuer、audience、exp/iat/sub，再映射 viewer/operator/admin。

05 · Delivery

怎麼證明不是 demo code？

30 automated tests、real Redis integration、Docker/Compose/Helm gate、pip-audit、GitHub semantic release、Kubernetes hardening 與 observability。

Trade-off

哪些地方刻意沒有做？

不把 RAG、MCP、Agent orchestration 塞進 Gateway；Anthropic/Gemini v0.5 仍是 normalized buffered streaming。清楚保留下一版演進空間。

Interview Q&A

可能被追問的技術問題

點擊展開。回答刻意保留 trade-off，不把每個設計包裝成「唯一正解」。

Q1. 為什麼不用每個 Application 直接呼叫 LLM Provider？
直接呼叫會讓 SDK、Credential、Retry、Fallback、Budget、Policy、Observability 分散到每個 Application。Gateway 讓這些 cross-cutting concerns 集中治理，同時保持 client 端 OpenAI-compatible。
Q2. Redis 在這裡只是 cache 嗎？
不是。v0.5 用它保存 distributed operational state 與 governance state：sliding-window rate limit、round-robin cursor、circuit breaker、usage/budget counters、dynamic aliases/pools/pricing/policies、managed client digests、audit events。
Q3. Policy Engine 和 Routing Policy 有什麼差？
Request Policy 決定「這個 Principal 可不可以提出這種 request」；Routing Policy 決定「允許之後，要選哪個 provider:model」。Policy 先於 routing。
Q4. OIDC JWT 驗證做了哪些事情？
透過 JWKS 取得 signing key，限制 algorithms，驗 signature、issuer、audience、exp、iat、sub；再從 configurable claim 映射 Gateway role。OIDC 是 optional，以維持 API key 相容性。
Q5. 為什麼 API Key 只保存 SHA-256 digest？
避免管理介面或 state backend 被讀取時直接暴露 plaintext。Managed key 只在 create / rotate 時回傳一次；rotate 後刪除舊 digest，舊 key 立即失效。
Q6. Streaming 的成本怎麼記？
Gateway 在 stream 完成且 provider 提供 usage metadata 時做 usage/cost finalization。OpenAI native stream 會要求 include_usage；若 upstream 不提供 usage，request 仍記錄，但 token/cost 可能為 zero/unknown。
Q7. NetworkPolicy 為什麼不是預設開？
不同企業的 CNI、Ingress topology、namespace selector、Redis location 不同。Chart 提供 reference baseline 並在 CI render 驗證，但正式環境必須依真實 dependency 收窄，而不是假設一份 policy 適用所有環境。
Q8. v0.5 最大的已知限制？
Anthropic / Gemini 目前透過 common provider contract 提供 normalized buffered stream，不是 native upstream progressive stream；Policy Engine 也是內建 runtime engine，尚未整合 OPA/Cedar 等 external PDP。
Trade-offs

已知限制與下一步

Portfolio 專案能清楚說出「沒有做什麼、為什麼、下一步怎麼做」通常比假裝所有問題都已解完更有說服力。

Native Streaming

Current: Mock / OpenAI native；Anthropic / Gemini normalized buffered fallback。
Next: provider-specific native stream adapters。

Policy Federation

Current: built-in first-match Policy Engine。
Next: OPA / Cedar external PDP、policy bundles、decision logs。

Enterprise Identity

Current: one configured OIDC issuer/JWKS。
Next: discovery、multi-issuer、groups/claims mapping、workload identity。

Multi-tenancy

Current: managed clients + per-client RPM。
Next: tenant quota、chargeback、cost center、tenant model allow-list。

Operations

Current: Redis readiness + PDB/HPA baseline。
Next: HA Redis strategy、SLO/SLA、alerts、chaos/failure testing。

Scope Discipline

Intentional: 不加入 vector DB、document ingestion、MCP server、agent orchestration，保持 Model Control Plane 清晰。
